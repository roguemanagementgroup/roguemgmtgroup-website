The Architecture

Capability is not authority.

An AI model can propose an action. A governed execution environment should decide whether that action is authorized, record the decision, and enforce the permitted scope.

01

Builder's Permit™

Identity- and scope-bound execution authorization designed to separate model planning from permission to act.

02

RogueOS™

A model-agnostic control-plane architecture for browser, API, filesystem, and other agent-driven operations.

03

Shadow Rogue™

A proposed operator-facing interface that exposes mission state, approvals, and governed execution rather than granting uncontrolled tool access.

We didn't build advisory software for boardroom slide decks. We built the tripwire that chokes off rogue execution before the first byte can cross the wire.

Core execution principle

Propose. Permit. Record. Execute. Revoke.

The Builder's Permit model specifies pre-execution checks, bounded authority, a write-ahead record, and a route to revocation and evidence reconstruction. These are architecture specifications; independent production conformance has not been established on this website.

Pre-execution authorization

A planner's proposal is not permission to execute.

Documented accountability

Evidence is intended to be recorded before side-effecting operations.

Human control

Human approval and revocation remain part of the control model.

You don't put a runaway machine on probation. You revoke its permit, sever its execution thread, and leave it dead in memory.
